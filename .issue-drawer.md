While the intelligence drawer is open, Tab cannot reach the error banner or the fatal-error overlay. Both paint above the drawer and stay clickable, so a keyboard user gets a screen that reports a failure and offers no way to act on it.

## The mechanism

`Drawer.tsx:70-95` binds the trap on `document`, but scopes the tab ring to the drawer panel (`drawerRef`, `:138`):

```ts
// packages/web-client/src/components/layout/Drawer.tsx:85-96
const inside = active instanceof HTMLElement && ring.includes(active);
if (event.shiftKey) {
	if (!inside || active === first) {
		event.preventDefault();
		last.focus();
	}
	return;
}
if (!inside || active === last) {
	event.preventDefault();
	first.focus();
}
```

The `!inside` arm is the defect. A trap needs to wrap at the ends — `last → first`, `first → last`. This one also captures every Tab pressed while focus is *anywhere else in the document* and pulls it back into the drawer. Nothing outside the drawer can be tabbed to for as long as it is open.

## What is above it

The drawer's own layer is `fixed inset-0 z-50` (`:124`). Two surfaces paint over it, from outside its subtree:

- `ErrorBannerStack.tsx:18` — `z-[60]`, appended after `children` in `ErrorBannerProvider.tsx:118-119`.
- `FatalErrorOverlay.tsx:107` — `z-[1000] … bg-red-700`, mounted as a sibling of the whole app at `routes/__root.tsx:74`.

Neither is inside `drawerRef`, so neither is in the ring.

## Reachability

At 1100px the drawer is the intelligence surface, and `IntelligencePane` is its only child (`IntelligenceDrawer.tsx:33-40`). Open a message, open the drawer, then:

- **Banner** — press Report spam and have the backend answer a 4xx. `useReportSpam.ts:168` pushes the banner; it paints over the drawer and its Dismiss and report-an-issue actions cannot be tabbed to. Nothing on the failure path closes the drawer.
- **Overlay** — let any query 5xx, including a background refetch, which `shell/index.tsx:56-58` escalates by default. `useIntelligenceData` polls from inside the drawer. The red full-screen overlay mounts and its Retry, Go to inbox, Report a bug and Copy details are unreachable; Tab focuses invisible drawer controls behind it.

`packages/e2e/specs/mid-width-intelligence.spec.ts` already drives the state the drawer is open in.

This is the failure mode the coding standard names: a user-facing failure that states what broke and offers a report link, with no way to press either.

## Done

Tab leaves focus outside the drawer alone and wraps only at the ring's ends, so the banner and the overlay are reachable while the drawer is open. #747's case — Tab walking *out* of the drawer onto controls buried under the scrim — still holds. Covered by a test that fails before the fix.

## Checked and deliberately not changed

`packages/ui/src/components/self-update-progress-overlay.tsx:31-51` has the same `!inside` shape. There it is correct: that overlay really is the topmost layer, so there is nothing above it to strand.

## Not established

Read from the source and the stacking layers; the app was not run and this was not reproduced in a browser. Escape does release the trap (`Drawer.tsx:71-74`), so a user who thinks to press it gets out. Pointer users reach every one of these controls.
