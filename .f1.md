On the self-host SQLite backend every configuration import runs in a transaction, so a mid-import failure writes nothing. The wizard's failure screen still marks every section before the failure as landed, with a green tick, under the headline "N of 5 sections landed" — directly above a banner reading "Nothing was written; the import stopped here."

## Where

The server is honest. `packages/backend/src/handlers/config.ts:290` passes `transaction: client.writeSet`, so `atomic` is true on self-host, and `packages/config-transfer/src/import.ts:1013` collapses the progress:

```ts
const landed = atomic ? emptyProgress() : progress;
```

`applied` is then `landed.items.length > 0` — `false` — and `items` holds only the one `Rejected` entry.

The client ignores both. `packages/web-client/src/lib/config-import.ts:316-320` skips rejected items when counting, so `counts` is empty, and `:355-365` still returns:

```ts
return {
	section,
	title,
	state: "landed" as const,
	detail:
		written === 0
			? "Nothing in the file for this section."
			: `${written} ${written === 1 ? "entry" : "entries"} written.`,
};
```

`packages/web-client/src/components/config-import/steps.tsx:712` maps `landed` to an "ok" green `CheckRow`, and `:729,739` render the "N of 5 sections landed" count.

The module's own docstring at `config-import.ts:305-307` states the invariant this breaks:

> Telling someone their accounts are in when nothing said so is the one answer this screen must never give.

The server did say so, in `applied`. The screen does not read it.

## Reachability

`ConfigImportWizard.tsx:327` routes to the `"partial"` screen on `writeFailure(answer)` without consulting `applied`.

`packages/drizzle-service/src/repos/config-import-atomicity.sqlite.test.ts:144-204` already builds exactly this report against a real SQLite savepoint, with a document carrying one account and one label, and asserts `applied === false`, empty `items`, and a message matching `/Nothing was written/`. Feed that same report to `sectionResults` and Accounts and Labels both come back `landed`, detailed "Nothing in the file for this section."

## Not already covered

Every `sectionResults` case in `packages/web-client/src/lib/config-import.test.ts:125-279` uses the non-atomic shape — `items` populated, message "The items above it were written and remain". The atomic shape has no test.

## Fix

`sectionResults` must read `report.applied`. When it is `false`, no section is `landed`: they were rolled back, and the subtitle should say the import was undone rather than counting sections that survived.
