A calendar's display name is written into the `.ics` feed without RFC 5545 escaping, so a name containing a comma, a semicolon, a backslash or a newline corrupts the feed — and a name containing CRLF injects a whole VEVENT into it.

## Where

`packages/calendar-service/src/feed.ts:109`:

```ts
feed.updatePropertyWithValue("x-wr-calname", collection.displayName);
```

ical.js escapes TEXT values for properties in its design set — `SUMMARY`, `DESCRIPTION` and the rest — but `X-WR-CALNAME` is not in it, so the value is serialized verbatim.

Against ical.js 2.2.1, a `displayName` of:

```
Work\r\nBEGIN:VEVENT\r\nUID:injected\r\nDTSTART:20250101T000000Z\r\nSUMMARY:pwned\r\nEND:VEVENT
```

serializes those CRLFs literally. Line folding splits one line mid-token, but unfolding at the subscriber restores a complete extra VEVENT. The mundane case matters too: an ordinary name like `Work, Home` is emitted as a bare TEXT value list rather than one escaped value.

## Reachability

`pickCalendarUpdate` (`packages/backend/src/handlers/calendar.ts:247`) copies `displayName` through with no validation. `String140` (`typespec/lib/scalars/string.tsp:20-21`) is `@maxLength(140)` with no pattern, and the payload above fits inside it. Nothing strips control characters between the PATCH body and the column.

`feed.test.ts:119-131` covers only the happy `X-WR-CALNAME:Team` case.

## Scope

On a single-user self-host the injector is the calendar's own owner, so this is corruption rather than privilege escalation. The audience is whoever holds the feed URL — the subscribed client on a phone or a desktop, which sees an event nobody created.

## Fix

Escape the value per RFC 5545 3.3.11 before setting it, or reject CR and LF where the collection is written. Cover a name carrying a comma, a semicolon, a backslash and a newline in `feed.test.ts`.
