`remit config save` writes the configuration document at the caller's umask — 0644 on a default-umask VPS. It is the one file the operator is told to keep, and it carries the address book, filter text, mail excerpts and signatures. Every other sensitive file the wrapper writes is deliberately 0600.

## Where

`deploy/vps/remit:3427` builds the temp path and `:3432`/`:3435` write to it:

```sh
_tmp="$_dir/.$(basename "$_file").writing.$$"
...
compose run --rm --no-deps -T migrate \
	node config-save.mjs >"$_tmp" || _rc=$?
```

then `:3452` `mv "$_tmp" "$_file"`. No `umask`, no `chmod`, no `trap`.

The wrapper elsewhere takes explicit care. `deploy/vps/remit:1256-1263` (`atomic_write`) sets `umask 077` for the breadcrumb, which carries nothing sensitive. `:510-526` (`set_var`) does the same, and its comment states the reasoning — a post-hoc `chmod` "leaves the secrets world-readable for the length of the write".

## What the file contains

The "no credentials" promise holds, and is worth stating because it is what makes this a permissions bug rather than a credential leak. `packages/config-transfer/src/export.ts:202-239` builds each account field by field with no credential field; `packages/config-format/src/document.ts` closes every object with `strictObject`; `packages/config-format/src/read.ts:28-40,99-102` refuses any unrecognised key whose name looks like a credential.

What it does carry:

- every flagged sender's address, display name and free-text `reason` (`export.ts:295-323`)
- every filter's literal clause values
- each filter anchor's `sourceText` — up to 512 characters of an actual email (`document.ts:212`)
- signatures, plain text and HTML
- account email addresses, usernames, and IMAP/SMTP endpoints

## Reachability

`deploy/vps/README.md:555` documents `remit config save reader-config.json`, run from an interactive shell. A default `umask 022` gives 0644 — readable by every account on the box.

`npm-scripts/lib/remit-config-save.test.mjs` asserts the bytes and the cleanup, never the mode.

## Fix

Wrap the redirect in a `umask 077` subshell, the way `set_var` already does, and add a `trap` so an interrupted run removes the `.writing.$$` file. Assert the resulting mode in `remit-config-save.test.mjs`.
